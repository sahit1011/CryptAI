BACKEND / THE THREE PLANES — HOW A TICK BECOMES A TRADE

Shared facts, per-user judgment, unmetered protection

PLANE 1 · SHARED — USER-BLIND, O(1) IN USERS

Rust engine: ingest (klines WS · book REST) → feature store → 5 vetoes → 6 weighted factors → regime + tradability 0–100 → market:pulse:SYMBOL, refreshed ≤5s, TTL 120s.

SHARED LLM ANALYSIS

Data → Analysis → Strategy agents produce a candidate-setup pool per symbol (SharedSetupCache) — computed once per cycle for everyone, demand-gated.

NEW · HOT-WINDOW SURFACE

market:pulse:global — cross-symbol "hot / quiet" now-cast + slots-aware nudge. Every pulse also appends to pulse_snapshots so the score stays falsifiable.

The pulse carries facts and scores only — never a direction, entry, or stop. Regime→direction was refuted out-of-sample; a contract test enforces the ban.

→
PLANE 2 · PER-USER — O(N) IN ACTIVE SCANS

SessionWorker (metered, 1 per scan): reads prefs + fresh pulses — fail-closed at 15s staleness — then analyze_fn: pulse gate → style filter → per-user synthesis (LLM selects the candidate that fits this trader and writes the thesis in their terms — it never invents a price) → deterministic sizing vs the user's own risk rules.

PROPOSAL (POSTGRES)

entry / stop / targets / size / leverage / R:R / rationale / shelf life. Clock pauses while the user decides. Approval re-validates at the live price — drift >0.5% refuses rather than fills worse than agreed.

Per-user LLM budget: analyze_fn returns real usage; the cap guards a moving number, fail-closed.

FIX BEFORE ENABLING THE PLANE

Confirmed bug: the pipeline calls .get() on Pulse dataclasses — enabling SIGNAL_PLANE_ENABLED today fails every metered cycle while the user's clock drains. Normalize at the boundary (as monitor_worker already does) + fold pulse liveness into the capacity check so dead-plane time is refunded.

→
PLANE 3 · EXECUTION + WATCH

Per-user engine (paper or live) books the bracket. Two money gates fail closed: ENABLE_EXECUTION + LIVE_TRADING_CONFIRMED.

POSITIONMONITOR — UNMETERED

1 per open position. Time stop · profit give-back · conditions-turned (pulse drift) → reduce-only exit when the thesis breaks. Outlives the session, restarts, deploys; supervisor reconciles on boot.

BOOKKEEPING

Fill → trade entry row (memory loop feeds) → portfolio + history update → session slot state advances (free tier: focus lock until flat).

BACKEND / SESSION LIFECYCLE — THE SLOT MODEL

The session state machine, extended for slots and trade focus

The metered state machine exists and is well-tested. Two mechanics change for the new product: quota becomes 2 discrete slots/day (not a minutes pool), and a focus lock holds new slots while a free-tier position is open.

Slot accounting (v2 — red-team hardened)

  • Today: one pooled 1800s/day quota for every tier, unlimited session count. Replaced by per-plan policy — and a slot is spent on proposal delivery, not scan start: a bounded scan (~10 min) with no qualifying setup auto-ends and returns the slot (scan attempts cap 3/day).
  • Slot-native refunds: a CAPACITY_LOST session re-opens its own slot with the remaining grant — never a fresh 30 min (flap test: capacity down/up ×5 must never mint extra scan time).
  • Race-safe consumption: partial unique index (one active session per user) + slot count and focus-lock check in one transaction; usage is derived (COUNT per trading day) — no stored counter, no reset job. Boundary stored UTC, rendered local.
  • The sweeper ends any SCANNING session past its grant, connection or not — ticks must not depend on an open WebSocket.

The focus lock (free tier)

  • Invariant: open_positions ≥ 1 ⇒ session_start refused, with the 409 distinguishing monitored from "position exists, monitor reattaching".
  • Source of truth: reconciled Redis + engine, with zombie auto-drop in the lock check — which is why restart-safe rehydration (R2.4) ships before the lock (R2.2). /api/positions/close stays the escape hatch.
  • A slot held by the lock survives exactly one midnight reset (intraday holds span midnight routinely).
  • Paid tiers raise the concurrency cap; at the cap an async session pauses unmetered (new held-at-cap state, mirroring the proposal pause) — skipping synthesis alone would still burn the user's clock.

Reject / expire / end paths

  • Reject or shelf-life expiry → back to SCANNING, clock resumes — covered today.
  • Approve → the session ends as trade_opened (slot spent well). "Trade focus" is a derived UI state — open position + monitor status, no session row and no session clock.
  • Quota spent or user ends → ENDED; open positions keep their monitors — quota never stops a monitor.

The cost law (write it into CLAUDE.md, enforce in review)

Every stream, loop, and LLM call must name its consumer. Subscribing at process startup is forbidden; tie it to a live session, a live viewer, or an open position — with a linger, then release. Before adding any network loop: bytes/day × 30 must fit the 5GB/month workspace budget with headroom (doc 05 has the ledger).

Debts acknowledged, scheduled, not blocking free launch

  • Money as floats everywhere except llm_cost_micros — one wholesale integer-minor-units + currency migration lands before any real-money path opens (roadmap gate, doc 06). Paper-only launch tolerates floats; real money never will.
  • RLS defense-in-depth on the five new per-user tables — backend bypasses RLS, so app-layer user_id filters remain the only guard; RLS is the second lock.
  • Alembic vs checkfirst collision — stamp the production DB once, then forward-only migrations in the deploy step.

Tenancy invariants (tested, keep enforcing)

  • Every per-user table carries an indexed user_id; pulse_snapshots must never gain one — schema-parity test enforces both.
  • Every new query filters user_id in app code; a missing filter is a launch blocker, not a bug.
  • Per-user Redis keys stay namespaced state:{user_id}:*; pulse keys stay global.

Hardening that rides along (from the audit, doc 01)

  • require_admin fail-closed; anonymous fail-open mode impossible in prod config
  • WS auth moves from ?token= query param to first-message auth (JWTs out of proxy logs)
  • The static NEXT_PUBLIC_API_TOKEN tier dies — Supabase JWT is the only client credential
  • Destructive one-off scripts leave the image (attic'd + .dockerignore)

Contract rules

  • Every tenant endpoint requires the JWT and scopes by user_id — /api/setups's unauthenticated broadcast model is retired with the v2 daemon path.
  • Pulse responses carry as_of + schema version; consumers reject stale or unknown-major — same contract the workers obey.
  • Errors are honest: capacity down = 503 + "engine unavailable", never a silent empty list.
