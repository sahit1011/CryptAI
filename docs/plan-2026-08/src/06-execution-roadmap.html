ROADMAP / THE HARNESS — HOW VIBECODING STAYS ON-PLAN

The harness: rules the repo now enforces, not hopes

Gates (mechanical)

  • .claude/verify.sh runs on every stop — typecheck, 99 frontend + 687 backend tests, import smoke, 38s. A red gate sends the work back; the gate is never weakened to pass.
  • Branch per unit of work (feat/ fix/ chore/); never commit to the default branch; small commits that say why.
  • npm run build before push (7s warm); cargo test for engine changes (cargo lives at /opt/homebrew/opt/rustup/bin — not on default PATH).
  • Docs of record: CLAUDE.md → docs/ARCHITECTURE.md → docs/plan-2026-08/. A session that contradicts them updates them or stops.

Laws (this repo's scar tissue)

  • The wiring law: "tested" ≠ "wired". No feature is claimed done without a constructor traced from server.py or the daemon. This repo's signature failure, three audits running.
  • The cost law: every stream, loop, and LLM call names its live consumer, or it doesn't ship. Bytes/day × 30 vs the 5 GB ledger, in the PR description.
  • The money law: never widen a risk gate, cap, or stop to get green; ENABLE_EXECUTION and LIVE_TRADING_CONFIRMED stay fail-closed; every query filters user_id.
  • The honesty law: no fabricated numbers in the UI; no directional claim from regime; no forward "hottest hour" until logged data earns it.

Session ritual (for every future AI coding session)

  • Open with: read CLAUDE.md → the current milestone in doc 06 → pick ONE task ID (e.g. R2.4). Out-of-plan work needs a written reason in the commit.
  • Mid: establish what runs before changing it; prefer deleting to commenting; new files must appear in pytest --collect-only.
  • Close with: verify.sh green · task's definition-of-done demonstrated (command output or screenshot, not narrative) · CLAUDE.md updated if reality moved.
  • Quarantined tests: read the failure before blaming the test — some encode real regressions.

R3 + R4 in one line each

R3 (trust): retire the static admin token · anonymous fail-closed · WS auth out of the URL · /metrics behind auth · global LLM request counter (fail-closed) · recap cards · forgot-password. R4 (launch): honest free-beta landing (no purchasable pricing) · cohorts of 10/day · product metrics live (activation, slots, approval rate, monitor saves) · hot-window nudge · week-one incident watch.
