UI/UX / DESIGN LANGUAGE & PRINCIPLES

The terminal aesthetic stays — the rules get written down

Visual system of record (frontend/DESIGN.md — shipped, keep)

  • "Terminal-grade restraint": near-black neutral canvas, crimson as the single brand hue (deep maroon fills, never full-bright red buttons), depth via hairlines — no shadows or glows as structure.
  • Emerald and red are reserved for P&L semantics only — untouchable by branding. Amber = warning, blue = info.
  • Geist for UI, Geist Mono for every number (tabular, slashed zero); Instrument Serif italic for hero-scale accent words only.
  • Dark-only, radii strictly 4/6/8px, motion restrained (150ms color transitions; bounce/shine/gradient-text banned).

Non-negotiable UX rules

  • No fabricated numbers. Every value traces to the backend or shows an honest empty/loading/error state. A dash is better than a guess.
  • Every wait is explained. Session synthesis in progress, engine warming up, proposal expiring — each has visible state, never a dead spinner.
  • Money actions confirm once, clearly — amount, worst-case loss, venue — then execute without ceremony.
  • The agent is visible. Users see what the system is doing (scanning, gating, watching) — trust comes from legibility, not claims.
  • Paper mode is labeled everywhere — a persistent chip, so nobody mistakes simulation for money.

UI/UX / FLOW A — FIRST RUN

Onboarding: Google in, five questions, trading in under two minutes

1

Sign in with Google

One button. Email/password stays available but Google leads. No email verification detour on the happy path.

→
2

Trading mode

Paper (recommended, instant desk) or Real — real routes through exchange connect (Delta India / BingX, testnet-first) with key verification.

→
3

Capital

"How much are you trading with?" Seeds the paper desk and anchors all sizing. Slider + input, sensible bounds.

→
4

Risk appetite

Conservative / Balanced / Aggressive cards — each shows what it concretely means: risk per trade, max leverage, min R:R.

→
5

Risk budget

"How much are you willing to risk per month?" (e.g. 2–10% max drawdown). Shapes pacing and per-trade risk. Never a return expectation — an asked-for +5% is a promise no evidence supports.

→
✓

Dashboard

Lands on the hot-window banner + 2 session slots ready. First-run coach marks point at the session button.

Design intents

  • Every answer shows its consequence ("Balanced = risking ~₹800 of your ₹80,000 per trade") — settings feel like decisions, not forms.
  • All five answers editable later in Preferences — onboarding is a default-setter, not a contract.

Real-mode branch

  • Exchange connect asks for trade-only API keys, links the how-to per exchange, verifies before storing (encrypted vault).
  • Mainnet keys accepted but execution stays testnet/paper until the compliance gate ships — copy says so plainly.

Edge states

  • Key verification fails → inline reason (wrong scope, IP allowlist, expired) + retry; never a dead end.
  • Abandoned mid-onboarding → resume at the same step on next login.
  • Skipped risk budget → conservative default (5% max monthly drawdown), flagged in Preferences — never a return number.

UI/UX / FLOW B — THE DAILY LOOP

The daily loop: check heat → spend a session → let the monitor work

1

Open app

Hot-window banner answers "worth trading now?" — market heat, per-symbol pulse, slots remaining (2/2). No session cost to look.

→
2

Start session

One tap. 30:00 server clock starts. Agent activity feed goes live: scanning symbols, reading pulse, gating risk — visible work.

→
3

Proposal arrives

Setup card slides in: side, entry, stop, targets, size, leverage, R:R, rationale, shelf-life countdown. Clock pauses. Approve / Reject.

→
4

Trade focus

On approve: re-validated at live price, executed, and the whole surface pivots to the running trade. No more setups this session.

→
5

Walk away

Session ends (or user leaves) — the monitor keeps working. Exit books P&L, updates portfolio + history, frees the next slot.

Session states the user sees

  • Scanning — timer runs, feed narrates agent work
  • Proposal — timer paused, decision card front and center
  • Trade focus — position header, monitor verdicts
  • Held — "trade open — slots preserved" when a new session can't start
  • Done — session recap: setups seen, action taken, P&L

A no-trade scan costs nothing

Qualifying conditions cluster in 1–2 windows a day — so most scans outside them should find nothing. The UI says "no qualifying setup — capital preserved, slot returned" (a slot is only spent when a proposal is delivered; scans cap at 3/day), shows what was evaluated and rejected, and steers to the hot window. First-run lands on the banner with "come back at the active hours" — never coach-marks Start at a random hour.

Re-engagement

  • Market turns hot + slots unused → one nudge (push/email), max one per day.
  • Trade closed while away → "your agent exited BTC +1.4R" notification linking to the trade recap.
  • 00:00 IST → slots reset quietly; no nagging.

Dashboard: heat up top, session in the center, agent always visible

Session panel (center stage)

Scanning: 27:14 clock + live agent narration.
Proposal: the decision card (below).
Trade focus: position hero + monitor verdict log.

Market pulse strip

BTC · ETH · SOL chips: regime label + tradability 0–100 + spark — from the Rust engine, not the LLM

Agent monitor window

Live feed: "12:41 pulse read BTC 71 · 12:41 risk gate passed 2.1% heat · 12:42 synthesizing long setup…" — the trust surface

Account chip

PAPER badge · tier · settings

Why this layout

  • Banner owns the top — the daily question ("trade now?") is answered before any click.
  • Session panel is the stage: its state drives the page; everything else is periphery.
  • Agent window is always on — even outside sessions it shows monitor heartbeats, so the product never looks dead.
  • Terminal stays a separate page for chart-first users; dashboard is decision-first.

The proposal card (the product's face)

  • LONG BTC · entry / stop / 2 targets · size & leverage · R:R 2.4 · risk ₹812
  • Two-line rationale in plain language + "what invalidates this"
  • Shelf-life ring counting down · Approve (success-tinted, per DESIGN.md) / Pass (ghost)
  • Approve = one confirm with worst-case loss, then execution state inline

UI/UX / TRADE FOCUS — THE SYNCHRONOUS PIVOT

Trade focus: when money is on the line, the UI has one subject

Position hero

LONG BTC-PERP · +₹1,204 (+1.1R) · entry 67,240 · mark 67,912 · SL 66,800 → tightened to 67,350 · TP1 hit ✓ · TP2 69,100 · elapsed 00:47

Chart with trade levels

Entry/SL/TP drawn on the live chart; monitor's invalidation level shown as a labeled line — the user sees exactly what the agent watches

Monitor verdict log

"13:02 thesis intact — structure holding · 13:17 TP1 filled, stop → breakeven · 13:29 pulse cooling, watching invalidation"

Manual controls

Close now · Move stop (tighten-only on free) — user always outranks the agent

Status footer

"Session complete — slot spent well · monitor on duty" · next-slot status (held while the trade runs)

Interaction rules

  • Trade focus is a derived state — open position + monitor status. The session ended the moment the trade opened (slot spent well); there is no session clock here to expire.
  • Monitor actions (tighten, partial, exit) appear as verdicts with reasons, timestamped, read from the append-only monitor_events trail — persisted, so the story survives restarts and feeds the exit recap.
  • Manual close always available, one confirm, shows realized P&L instantly.
  • The one banner: "session complete — your monitor is on duty."

Exit recap (the retention moment)

On close, a recap card: outcome in R and ₹, what the monitor did and why, updated equity curve, and — when slots remain and the market is still hot — "1 session left today". Every exit hands the user a reason to come back.
