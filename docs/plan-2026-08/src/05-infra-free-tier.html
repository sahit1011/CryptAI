INFRA / THE $0 BUDGET LEDGER

The bandwidth ledger: ~1.5 GB against a 5 GB cap

Render meters service-initiated traffic — our outbound subscriptions, not user requests. Budget: 5 GB/mo ≈ 167 MB/day ≈ 1.9 KB/s sustained. The target design spends less than a third of it.

⚠️ Never recreate the service

cryptai-backend was configured by hand, not from the Blueprint. Recreating mints a new URL and silently drops the 8 dashboard-only secrets — including VAULT_ENC_KEY, which encrypts every user's exchange keys. Losing it orphans every stored credential, unrecoverably. Resume; never delete-and-recreate.

Enabling the signal engine (R1, separate step)

  • Precondition: the Pulse-dataclass fix + klines-to-REST are merged.
  • Set RUN_SIGNAL_ENGINE_IN_API=true + explicit SYMBOLS (binary defaults to 5 symbols — more bandwidth than planned).
  • Watch logs for pulse publishes, then flip SIGNAL_PLANE_ENABLED=true. Never both blind — a dead plane silently drains user clocks (skipped_stale).

Branch & keepalive truth

  • GitHub default branch is still v2 — scheduled workflows run from it, so the live keepalive is the old always-green version. Make the m1 line the default (R1) to activate the fail-loud keepalive.
  • GitHub auto-disables cron workflows after 60 idle days — the keepalive is load-bearing (its death sleeps the daemon and kills monitors). Commit at least every 2 months or re-enable manually.
  • Rotate the Render API key (it was pasted into a chat on 2026-08-03).

Config truths

  • render.yaml is documentation, not the control plane — the live service was hand-configured; dashboard edits change production, blueprint edits don't. Keep them in parity by review.
  • Frontend env: NEXT_PUBLIC_API_TOKEN must stay unset forever — anything NEXT_PUBLIC_* ships in public JS, and this one is admin-capable.
  • Money gates stay untouched: USE_TESTNET=true, LIVE_TRADING_CONFIRMED=false, ENABLE_EXECUTION unset — never flipped to make anything "work".

Ops rhythm (10 min/week)

  • Render bandwidth graph — the one chart that predicts suspension; alarm bell at >100 MB/day sustained
  • Keepalive workflow green + not auto-disabled
  • Supabase DB size + project not paused
  • OpenRouter request usage vs daily cap
  • After any deploy: /health/ready + monitors-online log line
